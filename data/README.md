# Data Directory Architecture & Immutability Standard
**Problem Statement ID:** 26064  
**Module:** Seafloor Magnetic Anomaly Detection  

---

## 1. Directory Structure

```text
data/
├── raw/            # Read-only untouched magnetometer sensor payloads & field logs
├── processed/      # Validated, chronological, baseline-estimated datasets
├── features/       # Extracted feature matrices for model consumption
├── predictions/    # Standardized output JSON records with classifications
└── synthetic/      # Development & benchmarking synthetic datasets (pre-hardware)
```

---

## 2. Core Data Integrity Principles

1. **RAW DATA IMMUTABILITY (MANDATORY)**:
   - Files stored in `data/raw/` are strictly **read-only**.
   - No preprocessing, imputation, unit conversion, or filtering is permitted in-place on raw files.
   - Every raw file must retain original timestamps, hardware-reported coordinates, raw tri-axial flux values ($B_x, B_y, B_z$), and hardware metadata logs.

2. **REPRODUCIBLE DERIVATION**:
   - `data/processed/` files are generated by passing `data/raw/` through `src.preprocessing.preprocess_pipeline()`.
   - `data/features/` files are generated by `src.features.FeatureExtractor.extract_features()`.
   - Any derived dataset must be 100% reproducible from raw files and a specified configuration file.

3. **CLEAR SEPARATION OF STAGES**:
   - Raw sensor telemetry $\rightarrow$ `data/raw/`
   - Preprocessed / Baseline-subtracted $\rightarrow$ `data/processed/`
   - Model feature matrices $\rightarrow$ `data/features/`
   - Model inference predictions $\rightarrow$ `data/predictions/`
